# SOC Alert Triage Fundamentals

## 1. Introduction

Alert triage is one of the most important responsibilities of a Security Operations Center (SOC) Level 1 Analyst.

It is the process of reviewing, evaluating, and classifying security alerts to determine whether they represent genuine security threats or harmless activities.

SOC L1 analysts act as the first line of defense by identifying suspicious activities and escalating potential security incidents to higher-level analysts.

## 2. From Events to Alerts

Understanding how alerts are generated is essential for effective alert triage.

The process generally follows these steps:

1. **Event Generation:** An activity occurs, such as a user login, process execution, or file download.
2. **Log Generation:** The operating system, firewall, endpoint, or cloud service records the activity.
3. **Log Collection:** Logs are forwarded to a centralized security monitoring solution.
4. **Detection:** The SIEM or another security solution analyzes the collected logs using detection rules.
5. **Alert Generation:** When suspicious activity matches a detection rule, a security alert is generated.
6. **Alert Triage:** SOC analysts investigate the alert and determine the appropriate response.

## 3. What Is a Security Alert?

A security alert is a notification generated by a security solution when a specific event or sequence of events matches a detection rule.

Alerts help SOC analysts identify potentially suspicious activities without manually reviewing millions of raw log entries.

### Common Alert Examples

- Unusual Login Location
- Email Marked as Phishing
- Windows RDP Brute Force
- Potential Data Exfiltration
- Suspicious File Download
- Unauthorized Process Execution

## 4. Security Monitoring Solutions

SOC teams use different platforms to monitor and investigate security alerts.

| Solution | Examples | Purpose |
|---|---|---|
| SIEM | Splunk ES, Elastic | Collects and analyzes security logs and manages alerts. |
| EDR / NDR | Microsoft Defender, CrowdStrike | Monitors endpoint or network activities and detects threats. |
| SOAR | Splunk SOAR, Cortex SOAR | Automates and coordinates security response workflows. |
| ITSM | Jira, TheHive | Supports incident tracking and case management. |

## 5. Main Alert Properties

SOC analysts must understand the important fields associated with an alert.

| Property | Description |
|---|---|
| Alert Time | Indicates when the alert was created. |
| Alert Name | Provides a summary of the detected activity. |
| Alert Severity | Indicates the urgency and potential impact of the alert. |
| Alert Status | Shows the current investigation state. |
| Alert Verdict | Classifies the alert as a genuine threat or false alarm. |
| Alert Assignee | Identifies the analyst responsible for investigating the alert. |
| Alert Description | Explains the detection rule and why the activity may be suspicious. |
| Alert Fields | Contains relevant information such as hostname, username, IP address, and process details. |

## 6. Alert Severity Levels

Security alerts are commonly classified into four severity levels:

- **Critical:** Requires immediate attention because of potentially severe security impact.
- **High:** Indicates a serious security concern that requires prompt investigation.
- **Medium:** Represents a moderate security concern that should be investigated.
- **Low / Informational:** Indicates lower-priority activity that may still require review.

Severity helps analysts determine investigation priority.

## 7. Alert Status

Alert status indicates the current stage of an investigation.

Common statuses include:

- **New / Unassigned:** The alert has not yet been picked up by an analyst.
- **In Progress / Pending:** An analyst is actively investigating the alert.
- **Closed / Resolved:** The investigation has been completed.

## 8. Alert Verdict

The verdict determines the classification of an investigated alert.

### True Positive

A True Positive occurs when an alert correctly identifies genuinely suspicious or malicious activity.

Example: An alert detects unauthorized execution of a malicious program, and investigation confirms the activity.

### False Positive

A False Positive occurs when an alert is triggered by activity that is legitimate or harmless.

Example: A security rule detects an unusual login, but investigation confirms that the user was traveling and the login was legitimate.

## 9. Responsibilities of a SOC Team

**SOC L1 Analyst**
- Reviews incoming security alerts.
- Performs initial investigation and classification.
- Identifies suspicious activities.
- Escalates confirmed or suspected threats to L2 analysts.

**SOC L2 Analyst**
- Performs deeper investigation.
- Analyzes escalated security incidents.
- Supports containment and remediation activities.

**SOC Engineer**
- Maintains and improves detection rules.
- Ensures alerts contain sufficient information for investigation.

**SOC Manager**
- Monitors the overall SOC operation.
- Tracks investigation quality and performance.

## 10. Key Takeaways

- Alerts are generated from events and collected security logs.
- SIEM solutions help centralize security monitoring.
- Alert properties provide the information required for investigation.
- Severity determines urgency, while verdict determines classification.
- SOC L1 analysts perform initial alert triage and escalate potential threats.
